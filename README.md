# BONZY

**Любимые места. Новые поводы возвращаться.**

Первая рабочая версия гостевого приложения BONZY для iOS, Android и браузера. Написана на React Native и Expo SDK 58 с TypeScript. Тёплая светлая палитра, оранжевый акцент, зелёные бонусные карты, русский интерфейс и цены в тенге.

Это интерактивный MVP с локальными демонстрационными данными. Реальные рестораны, оплата, серверная авторизация и кассовые системы пока не подключены. APK/IPA не созданы; экспорт JavaScript/Hermes для обеих мобильных платформ проверен. Приложение ещё не проходило испытания на физических устройствах.

## Посмотреть сейчас

Открыть **http://localhost:4173** на компьютере, пока запущен сервер превью. В браузере можно проверить все сценарии, включая мобильную компоновку.

Для повторного запуска в Windows — `Start-BONZY.cmd` или команды:

```sh
pnpm install --frozen-lockfile
pnpm export:web
pnpm preview
```

Требуются Node.js 24 LTS и pnpm 11.25.0. Если используется PowerShell с запретом запуска скриптов, вводите `pnpm.cmd` вместо `pnpm`.

Для разработки с автоматическим обновлением: `pnpm web` (порт 8081). Для нативной разработки: `pnpm start`.

## Что работает

- Каталог шести вымышленных заведений Алматы, категории, поиск по названию, кухне и адресу, фильтр мест с накопленными бонусами и сортировка по рейтингу.
- Страницы заведений с адресом, примерным расстоянием, временем работы, меню по категориям и своей бонусной программой.
- Избранное, количество блюд, корзина одного заведения и явная замена корзины при смене ресторана.
- Демооформление заказа с собой или к столу с проверкой номера стола и комментарием.
- Отдельные балансы каждого бренда, списание до 30%, начисление на сумму после скидки, отмена заказа с обратной бонусной операцией.
- История и подробности заказов; ручная отметка демозаказа полученным.
- Обмен баллов на подарок, список купонов, персональный демонстрационный QR и редактирование имени.
- Сохранение профиля, корзины, избранного, заказов, балансов и купонов через AsyncStorage. Повреждённое сохранение сбрасывается к исходным данным.
- Адаптивная компоновка: нижняя навигация на телефоне, верхняя на широком экране; безопасные отступы и обработка Android Back.

Доставка сознательно оставлена для этапа интеграций: у первой версии есть два завершённых сценария получения заказа. Геолокация не запрашивается: город и расстояния — демонстрационные. Экран уведомлений объясняет, что push ещё не подключён.

## Проверка сценария за две минуты

1. Открой AULA → добавь «Авокадо тост» → «К заказу».
2. Выбери «В заведении», укажи стол 12 и включи бонусы.
3. Из 3 200 ₸ спишутся 960 бонусов, тестовая сумма — 2 240 ₸; начислятся 224 бонуса AULA.
4. Создай демозаказ. Закрой окно и перезагрузи приложение: заказ останется в истории.
5. Отмени его: баланс AULA вернётся к 1 250. Другие карты не изменятся.
6. Для проверки подарка создай заказ на тост **без списания**. Баланс AULA станет 1 570; в «Мои бонусы» обменяй 1 500 на подарок. Купон сохранится ниже карт.

Деньги не списываются, заказы не уходят в рестораны. Купоны и QR не действуют на кассе. Все локальные суммы и операции предназначены только для демонстрации.

## iOS и Android

### Проверить BONZY на iPhone через Expo Go

В App Store на 14 ноября 2026 года указан Expo Go 58.0.5 с поддержкой SDK 58. Для такого тестирования не нужна платная подписка Apple Developer. Установите или обновите [Expo Go](https://apps.apple.com/app/expo-go/id982107779).

1. Создайте бесплатный [Expo-аккаунт](https://expo.dev/signup) и войдите в него в Expo Go на iPhone.
2. Подключите iPhone к той же локальной сети, что и компьютер с BONZY. Компьютер может быть подключён кабелем, а iPhone — по Wi-Fi к тому же роутеру.
3. На Windows запустите `Start-BONZY-iPhone.cmd`. При первом запуске войдите в **тот же Expo-аккаунт** в официальном Expo CLI. Пароль вводится непосредственно в терминале, а не в чат.
4. Откройте Камеру iPhone, наведите её на QR в появившемся окне и выберите открытие в Expo Go. Разрешите Expo Go доступ к локальной сети, если iOS его запросит.
5. Не закрывайте окно сервера на компьютере во время проверки. В приложение загрузится нативный интерфейс BONZY; отдельная иконка BONZY на домашнем экране при этом не устанавливается.

Если требуется открыть терминал вручную: `pnpm exec expo login`, затем `pnpm exec expo start --go --lan --port 8082`. QR на экране «Мой QR» внутри BONZY предназначен для демонстрации бонусной карты и не запускает приложение.

Если установленная версия Expo Go не поддерживает SDK 58, сначала обновите её в App Store и проверьте версию. Документация Expo о прекращении обновлений после SDK 54 противоречит текущей странице App Store; для этой инструкции проверена именно опубликованная версия приложения.

Одна кодовая база рендерится нативными компонентами React Native. Для разработки можно использовать совместимую со SDK 58 версию Expo Go, если она доступна для нужной платформы, или собрать отдельное приложение.

Подготовлены профили Expo Build в `eas.json`: `preview` для тестирования и `production` для будущей магазинной сборки. Android preview выдаёт APK. Bundle ID / package name: `kz.bonzy.app` — перед публикацией нужно подтвердить владение выбранным идентификатором.

```sh
# Войти в свой Expo-аккаунт и связать проект
pnpm dlx eas-cli@27.10.0 login
pnpm dlx eas-cli@27.10.0 init

# Android: устанавливаемый тестовый APK
pnpm build:android

# iPhone: внутренняя сборка с подписью Apple и регистрацией устройства
pnpm dlx eas-cli@27.10.0 device:create
pnpm build:ios
```

Сборки требуют учётной записи Expo; iOS для установки на физический iPhone требует подходящей учётной записи Apple Developer и provisioning. Ключи и учётные данные в проект не включены. Команды сборки загружают исходники в ваш Expo-проект; стоимость и доступность сервиса определяются вашим тарифом.

Официальные инструкции: [создание сборки](https://docs.expo.dev/build/setup/), [APK](https://docs.expo.dev/build-reference/apk/), [внутреннее распространение iOS/Android](https://docs.expo.dev/build/internal-distribution/).

## Разработка и проверки

```sh
pnpm typecheck
pnpm test
pnpm exec playwright install chromium
pnpm test:e2e
pnpm export:web
pnpm export:native
pnpm format
```

Тесты логики проверяют раздельные балансы, лимит списания, начисление, повторное оформление, отмену, номер стола, подарки и восстановление данных. Playwright проверяет полный путь заказа, сохранение, поиск, избранное, QR, профиль и смену ресторана на мобильном и широком экране. Это браузерные проверки общей React Native Web реализации; они не заменяют испытаний нативной сборки.

`scripts/preview.mjs` снимает четыре превью при работающем сервере на порту 4173: главная на телефоне и компьютере, меню и бонусы. Фотографии включены в проект, не требуют запросов к фотосервису во время работы.

## Структура

```text
App.tsx                 навигация, сценарии, экраны, локальное сохранение
src/domain.ts           типы и чистая логика заказов и бонусов
src/data.ts             вымышленные заведения и демонстрационное меню
src/ui.tsx              палитра, стили, общие компоненты
assets/photos/          локальные фотографии еды и кофе
tests/domain.test.ts    проверки бизнес-логики
tests/e2e/              браузерные сценарии
previews/               снимки приложения
eas.json                профили устанавливаемых сборок
```

## Переход к реальному пилоту

Потребуются сервер и база данных, телефонная авторизация, серверный журнал бонусных операций, актуальные меню партнёров и кабинет ресторана. Клиентское состояние нельзя использовать как источник реальных балансов. Создание и отмена заказа, расчёт суммы, начисление и обмен на подарок должны стать серверными операциями с проверкой доступа и ключом идемпотентности.

Следом — одна подтверждённая кассовая интеграция, платёжный провайдер с чеками/возвратами, серверный QR с ограниченным сроком действия, push-уведомления, правила обработки данных и тестирование на физических iPhone/Android. Текущее приложение даёт готовый интерфейс и проверяемые пользовательские сценарии для этого этапа.

Фотографии: [Unsplash](https://unsplash.com/), иллюстрации демонстрационных блюд; идентификаторы исходных фотографий записаны в `assets/photos/SOURCES.md`. Иконки: [Lucide](https://lucide.dev/). Иконка BONZY генерируется из буквы `b` скриптом `scripts/generate-brand.ps1`.
